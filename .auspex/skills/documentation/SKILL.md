# documentation

- Say WHY, not what. The code already says what it does; it cannot say
  which alternative was rejected and for what reason.
- A README opens with what the thing is and how to run it. Not with a
  badge wall.
- Every example must actually run. An example that has drifted is worse
  than none, because it is trusted.
- Document the surprising, not the obvious. A comment on an obvious line
  trains the reader to skip comments.
- Match the tone already in the file. A document in two voices reads as
  unmaintained.
